Цель работы
Познакомиться с основами Docker: установкой и проверкой Docker, работой с образами и контейнерами, пробросом портов, просмотром логов, выполнением команд внутри контейнеров и использованием Docker volumes.
Также в рамках дополнительного задания было создано простое Flask-приложение, собрано в Docker-образ и запущено в контейнере.
Ход работы
1. Установка и проверка Docker
Docker Desktop был установлен на MacBook.
Для проверки установки была использована команда:
docker --version
Результат:
Docker version 29.8.0, build 88096ef
После этого был запущен тестовый контейнер:
docker run hello-world
В терминале появилось сообщение Hello from Docker!, подтверждающее корректную работу Docker.
Для просмотра образов и контейнеров были использованы команды:
docker images
docker ps
docker ps -a
Команда docker images показывает локально сохранённые Docker-образы.
Команда docker ps показывает запущенные контейнеры.
Команда docker ps -a показывает все контейнеры, включая остановленные.
2. Работа с образом Ubuntu
Сначала был загружен образ Ubuntu:
docker pull ubuntu:latest
После этого был запущен интерактивный контейнер:
docker run -it ubuntu bash
Внутри контейнера был установлен пакет curl:
apt update && apt install -y curl
Установка была проверена командой:
curl --version
После проверки работа с контейнером была завершена:
exit
Таким образом, был изучен запуск интерактивного контейнера и установка дополнительного программного обеспечения внутри него.
3. Запуск веб-сервера nginx
Для работы с веб-сервером был запущен контейнер с образом nginx:alpine:
docker run -d -p 8080:80 --name web-server nginx:alpine
Параметр -p 8080:80 настроил проброс порта 8080 на компьютере пользователя на порт 80 внутри контейнера.
Работа веб-сервера была проверена через браузер по адресу:
http://localhost:8080
Также состояние контейнера было проверено:
docker ps
Для просмотра логов использовалась команда:
docker logs web-server
В логах был зафиксирован успешный HTTP-запрос к главной странице:
"GET / HTTP/1.1" 200
Для подключения к контейнеру была использована команда:
docker exec -it web-server sh
После проверки из контейнера был выполнен выход:
exit
4. Управление контейнерами
Для управления контейнером web-server были использованы команды:
docker ps
docker stop web-server
docker start web-server
docker ps
docker rm web-server
После остановки контейнера его статус был проверен с помощью docker ps.
Затем контейнер был снова запущен командой:
docker start web-server
После завершения работы контейнер был остановлен и удалён:
docker stop web-server
docker rm web-server
Также был удалён использовавшийся образ:
docker rmi nginx:alpine
Таким образом, были изучены основные операции управления жизненным циклом Docker-контейнера и удаления Docker-образов.
5. Работа с Docker Volume
Для хранения данных независимо от жизненного цикла контейнера был создан Docker volume:
docker volume create my-volume
Затем был создан контейнер с подключённым volume:
docker run -it --name volume-test -d -v my-volume:/data ubuntu bash
Для подключения к контейнеру использовалась команда:
docker exec -it volume-test bash
В директории /data, которая связана с Docker volume, был создан файл:
echo "Hello from volume" > /data/test.txt
Содержимое файла было проверено:
cat /data/test.txt
Результат:
Hello from volume
После этого первый контейнер был удалён:
docker rm -f volume-test
Затем был создан новый контейнер с тем же Docker volume:
docker run -it --name volume-test-2 -v my-volume:/data ubuntu bash
После подключения к новому контейнеру:
cat /data/test.txt
было снова получено:
Hello from volume
Это подтвердило, что данные сохранились после удаления первого контейнера, поскольку они хранились в Docker volume, а не внутри самого контейнера.
6. Дополнительное задание — Flask-приложение
В рамках дополнительного задания было создано простое Flask-приложение.
Файл app.py
Приложение возвращает сообщение Hello from Docker! при обращении к главной странице.
Файл requirements.txt
Для приложения была указана версия Flask:
Flask==2.0.1
Werkzeug==2.0.3
Версия Werkzeug была зафиксирована дополнительно, поскольку при первоначальном запуске возникла ошибка совместимости Flask 2.0.1 с актуальной версией Werkzeug:
ImportError: cannot import name 'url_quote' from 'werkzeug.urls'
После добавления Werkzeug==2.0.3 приложение успешно запустилось.
Dockerfile
Для приложения был создан Dockerfile на основе python:3.9-slim.
В Dockerfile были выполнены следующие действия:
выбран базовый Python-образ;
установлена рабочая директория /app;
установлены curl и vim;
установлены Python-зависимости;
скопирован файл приложения;
создан пользователь appuser с UID 1000;
выполнен переход на пользователя appuser;
открыт порт 5000;
установлена переменная окружения FLASK_ENV=production;
задан запуск приложения через python app.py.
Сборка Docker-образа
Образ был собран командой:
docker build -t my-flask-app .
Сборка завершилась успешно:
FINISHED
Запуск контейнера
Сначала была выполнена попытка запустить приложение на порту 5000:
docker run -d -p 5000:5000 --name flask-container my-flask-app
Однако порт 5000 на Mac уже использовался системным процессом. Это было проверено командой:
lsof -i :5000
После этого контейнер был запущен с использованием свободного порта 5001 на компьютере:
docker run -d -p 5001:5000 --name flask-container my-flask-app
Здесь порт 5001 на компьютере перенаправляется на порт 5000 внутри контейнера.
Работа приложения была проверена командой:
curl http://localhost:5001
Результат:
Hello from Docker!
Таким образом, Flask-приложение было успешно собрано в Docker-образ и запущено в контейнере.
