# Ход работы

## 1. Проверка установки Docker и базовые команды

Первым этапом была проверена установка Docker.

Для просмотра установленной версии была выполнена команда:

```bash
docker --version
```

Результат:

```text
Docker version 29.8.0, build 88096ef
```

Полученный результат подтверждает, что Docker установлен и доступен из терминала.

### Запуск тестового контейнера

Для дополнительной проверки работоспособности Docker был запущен тестовый контейнер:

```bash
docker run hello-world
```

Docker автоматически загрузил образ `hello-world`, создал на его основе контейнер и запустил его.

В терминале появилось сообщение:

```text
Hello from Docker!

This message shows that your installation appears to be working correctly.
```

Таким образом, была подтверждена работоспособность Docker: клиент Docker смог обратиться к Docker Engine, получить образ, создать контейнер и выполнить его.

### Просмотр локальных образов

Для просмотра Docker-образов, которые уже находятся на компьютере, была выполнена команда:

```bash
docker images
```

Команда `docker images` показывает список локально доступных образов.

В ходе работы среди образов находились:

```text
hello-world
ubuntu:latest
nginx:alpine
```

### Просмотр контейнеров

Для просмотра только запущенных контейнеров использовалась команда:

```bash
docker ps
```

Для просмотра всех контейнеров, включая остановленные:

```bash
docker ps -a
```

Разница между командами заключается в том, что `docker ps` показывает только контейнеры, которые работают в данный момент, а `docker ps -a` показывает полную историю созданных контейнеров.

Например, после запуска `hello-world` контейнер завершил работу самостоятельно, поэтому он отображался в `docker ps -a` со статусом:

```text
Exited (0)
```

Код `0` означает успешное завершение процесса.

Таким образом, на первом этапе были изучены основные команды для просмотра состояния Docker, образов и контейнеров.

# 2. Работа с готовым образом Ubuntu

Следующим этапом была выполнена работа с готовым Docker-образом Ubuntu.

## 2.1. Загрузка образа

Для загрузки последней версии Ubuntu использовалась команда:

```bash
docker pull ubuntu:latest
```

Здесь:

* `ubuntu` — название образа;
* `latest` — тег, обозначающий последнюю доступную версию образа.

Docker загрузил образ из Docker Hub и сохранил его локально.

После этого образ стал доступен для создания контейнеров.

---

## 2.2. Запуск интерактивного контейнера

Для запуска Ubuntu в интерактивном режиме была использована команда:

```bash
docker run -it ubuntu bash
```

В команде используются следующие параметры:

* `-i` — сохраняет интерактивный ввод;
* `-t` — создаёт псевдотерминал;
* `ubuntu` — образ, на основе которого создаётся контейнер;
* `bash` — команда, которая запускается внутри контейнера.

После выполнения команды появилась возможность выполнять команды непосредственно внутри Ubuntu-контейнера.

---

## 2.3. Установка curl

Внутри контейнера был установлен пакет `curl`:

```bash
apt update && apt install -y curl
```

Команда `apt update` обновляет список доступных пакетов, а `apt install -y curl` устанавливает программу `curl`.

После установки была выполнена проверка:

```bash
curl --version
```

В результате была выведена информация о версии установленного `curl`.

Это подтвердило, что пакет был успешно установлен внутри контейнера.

---

## 2.4. Выход из контейнера

Для завершения интерактивной сессии была использована команда:

```bash
exit
```

После выхода процесс `bash`, являвшийся основным процессом контейнера, завершился.

Таким образом, было проверено, что Docker позволяет запускать готовые образы в интерактивном режиме и выполнять внутри них дополнительные команды.

# 3. Запуск веб-сервера Nginx

Следующим этапом было необходимо запустить веб-сервер на основе готового образа `nginx:alpine`.

## 3.1. Запуск контейнера

Для запуска Nginx была выполнена команда:

```bash
docker run -d -p 8080:80 --name web-server nginx:alpine
```

Разберём параметры команды:

* `-d` — запускает контейнер в фоновом режиме;
* `-p 8080:80` — связывает порт `8080` компьютера с портом `80` контейнера;
* `--name web-server` — задаёт контейнеру имя `web-server`;
* `nginx:alpine` — образ Nginx на базе Alpine Linux.

После выполнения команды контейнер был запущен.

Для проверки его состояния использовалась команда:

```bash
docker ps
```

В списке запущенных контейнеров появился:

```text
web-server
```

При этом в информации о портах отображалось сопоставление:

```text
0.0.0.0:8080->80/tcp
```

Это означает, что обращения к порту `8080` на компьютере перенаправляются на порт `80` внутри контейнера.

---

## 3.2. Проверка Nginx в браузере

Работа веб-сервера была проверена в браузере по адресу:

```text
http://localhost:8080
```

Открылась стандартная страница Nginx с сообщением:

```text
Welcome to nginx!
```

Это подтвердило, что:

1. контейнер Nginx успешно запущен;
2. веб-сервер внутри контейнера работает;
3. порт контейнера опубликован на компьютере;
4. к приложению можно обратиться через браузер.

---

## 3.3. Просмотр логов

Для просмотра логов контейнера была выполнена команда:

```bash
docker logs web-server
```

В логах присутствовала информация о запуске Nginx и обработанных HTTP-запросах.

В частности, обращение к главной странице завершилось кодом:

```text
200
```

HTTP-код `200` означает успешную обработку запроса.

Таким образом, логи дополнительно подтвердили, что браузер успешно обратился к Nginx.

---

## 3.4. Подключение к работающему контейнеру

Для подключения к уже запущенному контейнеру использовалась команда:

```bash
docker exec -it web-server sh
```

Команда `docker exec` позволяет выполнять дополнительные команды внутри уже работающего контейнера.

После подключения появилась командная оболочка контейнера.

Для выхода использовалась команда:

```bash
exit
```

Важно, что после выхода контейнер не остановился, поскольку завершилась только дополнительная оболочка `sh`, а основной процесс Nginx продолжил работать.

# 5. Работа с Docker volumes

Последним этапом основной части лабораторной работы было изучение Docker volumes.

Volumes позволяют хранить данные отдельно от контейнера. Благодаря этому данные могут сохраняться после удаления самого контейнера.

## 5.1. Создание Docker volume

Для создания тома была выполнена команда:

```bash
docker volume create my-volume
```

Docker создал том с именем:

```text
my-volume
```

Проверить существующие volumes можно командой:

```bash
docker volume ls
```

---

## 5.2. Запуск контейнера с подключённым volume

Для запуска контейнера Ubuntu с подключённым томом использовалась команда:

```bash
docker run -it --name volume-test -d -v my-volume:/data ubuntu bash
```

Основной параметр здесь:

```text
-v my-volume:/data
```

Он подключает Docker volume `my-volume` к директории `/data` внутри контейнера.

То есть:

```text
my-volume → /data
```

Все данные, записанные в `/data`, будут храниться в Docker volume.

---

## 5.3. Создание файла в volume

Для подключения к контейнеру была выполнена команда:

```bash
docker exec -it volume-test bash
```

После подключения в директории `/data` был создан файл:

```bash
echo "Hello from volume" > /data/test.txt
```

Для проверки содержимого файла:

```bash
cat /data/test.txt
```

Результат:

```text
Hello from volume
```

Таким образом, файл был успешно записан в подключённый Docker volume.

---

## 5.4. Проверка сохранения данных после удаления контейнера

Для проверки основной особенности volume контейнер `volume-test` был остановлен и удалён:

```bash
docker stop volume-test
docker rm volume-test
```

После удаления контейнера сам volume `my-volume` не удалялся.

Затем был создан новый контейнер с тем же Docker volume:

```bash
docker run -it --name volume-test2 -d -v my-volume:/data ubuntu bash
```

После этого содержимое файла было проверено из нового контейнера:

```bash
docker exec -it volume-test2 cat /data/test.txt
```

Результат:

```text
Hello from volume
```

Файл сохранился, несмотря на удаление исходного контейнера.

Это подтверждает основное назначение Docker volumes: **данные хранятся отдельно от контейнера и могут использоваться другим контейнером**.

# 6.  Дополнительная часть: создание собственного Docker-образа

В рамках лабораторной работы также была выполнена дополнительная задача со звездочкой — создание Dockerfile для Flask-приложения.

## 6.1. Создание Flask-приложения

Файл `app.py` содержит:

```python
from flask import Flask

app = Flask(__name__)

@app.route('/')
def hello():
    return "Hello from Docker!"

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
```

Приложение создаёт маршрут `/`, который возвращает сообщение:

```text
Hello from Docker!
```

Для запуска приложение использует порт `5000`.

---

## 6.2. Создание requirements.txt

Файл `requirements.txt`:

```text
Flask==2.0.1
```

Также для обеспечения совместимости использовалась версия:

```text
Werkzeug==2.0.3
```

---

## 6.3. Создание Dockerfile

Dockerfile был создан в соответствии с требованиями задания:

```dockerfile
FROM python:3.9-slim

WORKDIR /app

RUN apt-get update && \
    apt-get install -y curl vim && \
    rm -rf /var/lib/apt/lists/*

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

RUN useradd -m -u 1000 appuser

USER appuser

EXPOSE 5000

ENV FLASK_ENV=production

CMD ["python", "app.py"]
```

В Dockerfile реализованы все основные требования задания:

* используется `python:3.9-slim`;
* рабочая директория — `/app`;
* устанавливаются `curl` и `vim`;
* устанавливаются Python-зависимости;
* копируется `app.py`;
* создаётся пользователь `appuser` с UID 1000;
* приложение запускается от имени `appuser`;
* открывается порт `5000`;
* устанавливается `FLASK_ENV=production`;
* приложение запускается командой `python app.py`.

---

## 6.4. Сборка собственного образа

Для создания Docker-образа была выполнена команда:

```bash
docker build -t my-flask-app .
```

Здесь:

* `docker build` — команда сборки образа;
* `-t my-flask-app` — имя создаваемого образа;
* `.` — текущая директория используется как контекст сборки.

После завершения сборки образ `my-flask-app` стал доступен локально.

---

## 6.5. Запуск Flask-контейнера

Для запуска приложения использовалась команда:

```bash

```

В задании предполагалось использование:

```text

```

Однако порт `5000` на компьютере уже был занят. Это было проверено командой:

```bash

```

Поэтому для локального запуска был выбран свободный порт `5001`.

В результате:

```text

```

означает, что порт `5001` на компьютере связан с портом `5000` внутри контейнера.
